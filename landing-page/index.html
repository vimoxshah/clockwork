The problem

You already pay for a coding agent. It idles most of the day.

Not because it is bad. Because it only works when you remember to ask. So the same chores come round every week, and the work they do lives in terminal scrollback, cron tables, CI logs and chat threads: invisible, unrepeatable, unaccountable.

Act 01 · today

Your agents are everywhere. Their work is nowhere.

Recurring agent chores live in crontabs, shell scripts, CI pipelines and sticky notes. Nothing shows you what ran, what it cost, or what it quietly skipped.

Act 02 · with Clockwork

Human time and agent time, on one grid.

Subscribe your own calendar over read-only ICS and your meetings sit next to the agent's shift. You see what ran while you were heads-down, and what needs you now.

The product

A real calendar, not a cron file with a coat of paint.

Month and week views, RRULE and cron recurrence, missed-run policies, a per-repo mutex and a queue that says why it is waiting. Every screenshot below is the real app at v0.4.0.

How it works

Book. Run. Review. Repeat.

Book

Pick an agent profile, a repo, a budget and a time. One-off or recurring. Chain a second agent to run after the first.

Run

Your own CLI engine executes unattended inside an OS-sandboxed git worktree cut from your base branch. It cannot touch your checkout.

Review

A report lands in your inbox: summary, branch, diffstat, cost in dollars, full transcript. Risky actions paused and asked you first.

Repeat

Make it weekly. Search your retained history. Spend by task, provider and day, with the money-burning failures surfaced.

Why it is built this way

Built like a product, not a demo.

01A real calendar

Month grid, recurrence, missed-run policies, per-repo mutex, quiet hours. Scheduling is first-class, not an afterthought.

02Provider freedom

Claude Code, Codex, OpenCode and Hermes are detected automatically. Switch the engine per task without rebuilding anything.

03Human in the loop

Risky actions pause the run and ask you. An unanswered ask fails safe after a short window. Nothing is silently approved.

04Real isolation

Every run gets its own worktree and its own macOS Seatbelt profile. Writes locked to scope. SSH keys unreadable.

05Honest reports

What it did, what it skipped and why, what it cost. Secrets masked. Full-text search across everything you have retained.

06Local-first

SQLite in ~/.clockwork, loopback-only API, keys sealed in the macOS Keychain. No account, no cloud, no telemetry.

Agent library

Thirteen specialists, not thirteen blank prompts.

Each profile is an operating contract: mission, constraints, hard safety rules and an output contract, so "update my deps" does not turn into "rewrite my repo". These are the names you will see in the app.

  • ✚Dep Surgeonpatch and minor bumps proven by tests; majors get triage notes, never blind upgrades

  • ◎Bug Hunterevidence-first root cause, with file and line, before any fix
  • ⌕Code Reviewerread-only, severity-rated findings with evidence

Security

Trust is the feature. So the boundary is open.

Unattended code needs brakes that do not depend on the model's good intentions. Each layer below says what it does and, just as plainly, what it does not.

01Sandboxed execution

A per-run macOS Seatbelt profile. Writes are default-denied outside the run's own worktree. Every run has its own process group and is killed as a group.

02Credential hygiene

A sanitized child environment built from an allowlist. ~/.ssh, ~/.aws, ~/.gnupg, browser profiles and shell history are unreadable from inside a run.

03Hard budget bounds

A USD soft cap, a turn cap and a wall-clock timeout, enforced by the supervisor process outside the model.

04Approvals that fail safe

Sensitive tool calls pause the run and ask you. About two minutes without an answer means auto-deny, recorded either way.

05Audit journal

Every approval, denial and state change is written down. Reports mask secrets before they are stored.

06Local only

The daemon binds 127.0.0.1 with a bearer token file at mode 0600. No analytics, no account, no cloud component.

Audit it yourself. The Seatbelt profile, the credential deny-list and the run-environment allowlist (packages/runner/src/{sandbox,deny-list,run-env,service-path}.ts) are published under Apache-2.0 with the tests that prove them: the suite writes a fake secret into ~/.ssh and ~/.aws, then runs a real cat inside a real sandbox-exec and asserts it fails. Read it, run it on your own Mac. Clockwork itself stays proprietary; the security boundary is open.
What that does not prove. That the DMG you downloaded was built from this source: releases are built by GitHub Actions and the checksums are published, but a reproducible build is not yet supported. The Seatbelt profile also permits system-socket, so the ssh-agent claim holds because of the run-environment allowlist, not the sandbox. File reads inside a run are as broad as an interactive agent session on the same machine. Worktree isolation bounds mistakes, not adversaries. The full escape matrix and the prompt-injection stance are in docs/security.md.
The honest constraint. Jobs run when your machine is awake. Clockwork keeps a plugged-in laptop awake through booked windows and tells you loudly when sleep caused a miss. For true overnight runs, use an always-on machine. Better to say it now than at 2am.

Clockwork is not notarised by Apple yet. An Apple Developer certificate costs $99 a year and this is an early build, so the app is unsigned. macOS will refuse to open it until you clear the download quarantine flag. Better to say that plainly than have Gatekeeper call it "damaged".

Install with Homebrew (recommended)

$ brew tap vimoxshah/clockwork
$ brew trust vimoxshah/clockwork
$ brew install --cask clockwork
$ xattr -dr com.apple.quarantine /Applications/Clockwork.app

brew trust is required because Homebrew refuses casks from third-party taps by default; you are explicitly saying you trust this one. Homebrew verifies the SHA-256 before installing. Homebrew 6 removed --no-quarantine, so you clear the flag yourself, on a binary whose hash was checked for you. That is why this beats a raw download.

Or install the DMG by hand

# 1. verify what you downloaded
$ shasum -a 256 ~/Downloads/Clockwork_0.4.0_aarch64.dmg

# 2. open the DMG, drag Clockwork to Applications, then
$ xattr -dr com.apple.quarantine /Applications/Clockwork.app

# 3. launch it
$ open -a Clockwork

Step 1 should print the hash in checksums-sha256.txt. If it does not match, do not install it; tell me instead. Step 2 removes the quarantine flag macOS adds to downloaded files. Only run it on a file whose checksum you just verified.
