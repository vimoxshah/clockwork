# Clockwork — Tech Stack

Every load-bearing choice, its rationale, and what was rejected. Cross-referenced from `decisions/DECISIONS.md`.

| # | Layer | Choice | Rationale | Rejected alternatives |
|---|---|---|---|---|
| 1 | Execution engine | **Dual engine behind `AgentRunner` (ADR-016): headless Claude Code `claude -p` as the DEFAULT** (stream-json telemetry, permission-prompt MCP hook for HITL, `--resume`, per-run `.claude/` profile materialization — rides the subscription login, **no API key**), **Claude Agent SDK as the opt-in option** for API-key users | Meets users where their auth already is; the CLI *is* Anthropic's supported headless surface for subscription accounts, which also shrinks the R-5 policy risk. Capabilities feature-detected per engine (contract matrix), UI degrades honestly. We still write zero agent-loop code. | Raw Messages API + custom loop (months of rework, permission model from scratch); SDK-only (forces API-key economics on subscription users — rejected in round 2 of planning); CLI-only (closes the door on programmatic richness the SDK offers API-key users) |
| 2 | Desktop shell | **Tauri 2** | ~10MB installers, low RSS, native tray/notifications/autostart/updater, Rust shell hardens localhost token handling. UI is plain web tech. | Electron (viable fallback if Tauri friction bites — decision gate at end of Phase 1; ~150MB + heavier RSS); Swift/Kotlin native (kills single-codebase NFR-5) |
| 3 | UI framework | **React 18 + TypeScript + Vite** | Team fluency, ecosystem, fastest AI-assisted velocity. | Svelte/Solid (fine tech, smaller AI training corpus + component ecosystem for calendars) |
| 4 | Calendar component | **FullCalendar** (React) | The only battle-tested OSS calendar with month/week/day + drag-create + recurring-event rendering. Building a calendar is a known tarpit. | Schedule-X (younger, fewer views); custom (months) |
| 5 | Component kit | shadcn/ui + Tailwind | Speed + ownable code (no runtime dep). | MUI/Antd (heavier, harder to make feel native) |
| 6 | Daemon runtime | **Node.js 22 (LTS)** | Same language as SDK and UI; child-process + pgid control is mature; single-binary packaging via `pkg`-style not needed (ships inside app bundle with bundled Node). | Rust daemon (better RSS but splits the codebase and slows every feature; SDK is TS-first); Bun (child-process/IPC edge cases too risky for a reliability product) |
| 7 | Daemon HTTP | Fastify + SSE | Tiny, fast, schema-validated routes (zod). WebSockets unnecessary — SSE is one-directional events + REST commands. | Express (fine, slower validation story); gRPC (overkill for loopback) |
| 8 | Service install | launchd LaunchAgent (mac) / systemd --user (linux) / Windows autostart + Job-Object supervision (post-v1) | **Login-session scoped, honestly**: starts at login, restarts on crash (KeepAlive/Restart=on-failure). No claim of logout survival — that's LaunchDaemon/system-service territory and out of H1 scope. Health-checkable; `clockworkd doctor`; single-instance lock. | System-level daemons (root, permission-model violence for a user tool); `node-windows` as primary Windows path (flaky — evaluate vs native Job wrapper post-v1) |
| 9 | Storage | **SQLite (WAL, `synchronous=FULL` on state transitions) + better-sqlite3 + Drizzle ORM**; transcripts/artifacts as files under `~/.clockwork/runs/<id>/`, DB keeps summaries + pointers | Local-first, zero-infra, transactional occurrence-claims + FSM; blobs out of the DB keeps it fast at 10k runs. | Postgres (infra for no reason); JSON files (no transactions — FSM corruption guaranteed); transcripts as DB blobs (bloat, slow backups) |
| 10 | Scheduling lib | **rrule** (iCal expansion) + croner (cron strings) + **Luxon** (tz/DST) | RRULE is the lingua franca of recurrence (also enables iCal export later); Luxon handles IANA zones + DST edge resolution explicitly. | node-cron alone (no RRULE, naive tz); date-fns-tz (weaker DST disambiguation API) |
| 11 | IDs | ULID | Sortable, collision-safe, embeddable in branch names. | UUIDv4 (unsortable), autoincrement (merge/export hostile) |
| 12 | Git operations | System `git` via child_process (+ `gh` CLI optional for PRs) | Worktrees, fetch, diffstat — battle-tested; users already have it; no lib can match worktree semantics. | isomorphic-git/nodegit (worktree support weak/abandoned) |
| 13 | Delivery channels | **Daemon-side native notifier** (macOS `osascript`/UNUserNotification helper, Linux `notify-send`, Windows toast) — the daemon must notify with the UI closed, so it cannot ride Tauri's notification API; tray/UI is the rich surface when open. Chat channels behind one `DeliveryChannel` interface: **Telegram Bot API** (plain fetch, no lib needed, M2) · **WhatsApp via user-configured gateway** (Meta Cloud API / Twilio / self-hosted bridge — we POST to the gateway, never speak WhatsApp, M3) · **generic HMAC-signed webhook** (fronts Slack/Discord/ntfy, M3) · nodemailer SMTP (M3). | Tauri-only notifications (silent when UI closed — breaks S-60); embedding a WhatsApp client library (unofficial libs violate WA ToS — gateway model keeps us clean); push services (H2 relay problem) |
| 13c | Search | **SQLite FTS5** (`search_idx` virtual table, porter tokenizer) + `GET /search` + ⌘K palette (cmdk-style component) | Full-text over tasks/runs/transcripts/profiles with zero new infra — it's already our database; local-only like everything else. | Embedded vector search (overkill for H1 — revisit for semantic "find that run about auth" in H2); lunr/minisearch in UI (re-indexes on every load, can't search transcripts on disk) |
| 13d | Widgets | **Clockwork Mini**: compact always-on-top Tauri window fed by `GET /widget/snapshot` (M3, cross-platform). **macOS WidgetKit**: native Swift extension reading a shared JSON snapshot (post-v1 — needs an Xcode companion target). | Glanceability without opening the app; snapshot endpoint keeps widgets dumb and safe (read-only, no token scope beyond snapshot). | Electron-style hidden webviews pretending to be widgets (RAM cost, uncanny); skipping WidgetKit forever (macOS users expect real widgets) |
| 13b | Run containment | **macOS Seatbelt (`sandbox-exec` profile) / Linux bubblewrap** per run — FS allowlist, credential-path exclusion (FR-26) | The actual security boundary; same family of mechanisms the Claude Code toolchain itself uses for sandboxing. | Docker/containers (heavyweight, repo-mount friction for H1 — revisit for H2 content-sandboxing); pattern-match deny-lists as the boundary (theater — review finding #10) |
| 14 | Secrets | OS keychain via Tauri plugin (mac Keychain / DPAPI / libsecret) | Delivery creds (Telegram bot token, gateway keys, webhook secrets, SMTP) never in SQLite (NFR-4). | Encrypted file (weaker, custom crypto smell) |
| 15 | Packaging/updates | Tauri bundler + tauri-updater; signed DMG + MSI + AppImage; npm-distributed CLI shim later | Auto-update is table stakes for a daemon product (security patches). | Manual downloads only (stale daemons forever) |
| 16 | Testing | Vitest (unit) · Playwright (UI) · **fake-clock harness for the scheduler** (deterministic time travel across DST fixtures) · a `MockRunner` implementing `AgentRunner` for full-loop tests without API spend | The scheduler and FSM are the product; they get the deepest tests. Real-SDK smoke tests run nightly with a $2 budget cap. | |
| 17 | Repo layout | pnpm monorepo: `packages/daemon` · `packages/runner` · `packages/ui` · `packages/shared` (types, API client, zod schemas) | Runner isolated so ADR-007 (multi-vendor seam) is structural, not aspirational. | |

## Version pins (at kickoff; revisit each phase)

Node 22 LTS · Tauri 2.x · React 18 · `@anthropic-ai/claude-agent-sdk` latest stable (pin minor; the SDK moves fast — see R-2 in risks) · better-sqlite3 12.x · rrule 2.8 · Luxon 3.x · FullCalendar 6.x.

## Deliberate debt (accepted for H1)

- No i18n scaffolding (retrofit cost acknowledged).
- Capacity model is heuristic (observed usage + plan-type priors), not an official quota API — Anthropic exposes none; treat as estimate UX, never a guarantee.
- Windows is post-v1 entirely (service supervision, Job Objects, power events, toast notifications all need their own hardening pass — review findings #19/#20).
- SDK pinning means new Claude features lag until we bump — acceptable; the alternative (floating latest) risks silent behavior change under scheduled unattended runs, which is worse.
